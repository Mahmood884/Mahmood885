# CH341A Programmer — WCH 1A86:5512

## 0. الهوية
- شريحة مؤكدة: QinHeng CH341 في وضع **EPP/MEM/I2C/SPI programmer** (PID 5512 = وضع الـ parallel/EPP mode حسب جداول WCH؛ وضع UART هو 7523).
- ⚠ البند الذي تركه تقرير المرحلة مفتوحاً: **ربط هذه الوحدة الفيزيائية بأي منظومة هي بالضبط** (هل ملحق منفصل لأغراض bench EEPROM/SPI flash أم جزء من طقم KTMFLASH؟) — يحتاج وصلة فردية ثانية مع ملاحظة اسم السلسلة/الملصق.

## 1. طبيعة العمل (مختلفة عن بقية الأجهزة)
CH341A ليس وسيط سيارات إطلاقاً — إنه **مبرمج ذاكرة مباشر**: 24-series EEPROM، 93-series MICROWIRE، SPI Flash 25-series، وEPP موازي. يعني ذلك:
- لا يوجد "بروتوكول ECU" هنا؛ البروتوكول = إشارات برمجية على الخطوط (I2C addr/RW أو SPI opcode مثل 0x03 READ / 0x06 WREN / 0x20 ERASE).
- مكتبات موجودة ومفتوحة بالكامل تجعل الطبقة الرابعة شبه جاهزة: **ch341a-python / Neodry's ch341a library / Asprogram open-source**. أدواتنا ستتكامل معها بدل أن تعيد اكتشافها.

## 2. خطة سريعة
```bash
sudo python3 tools/usb_id.py --vid 0x1A86 --json reports/data/ch341_scan.json
# driver kernel المتوقع: no one (userspace via libusb) — perfect for us
pip install pyusb
python3 -c "import usb.core; d=usb.core.find(idVendor=0x1a86,idProduct=0x5512); print(d)"
```
ثم قراءة EEPROM اختبارية معلومة المحتوى → إثبات chain: chip-select/address/opcode mapping عبر تحليل استدعاءات libusb (frida على أي GUI يستخدمه المستخدم، أو مباشرة من مكتبتنا).

## 3. قيمته لمشروعنا المستقل
عندما نريد dump/reflash **EEPROM خارج الـ ECU case** (bench) أو TCU flash chips، CH341A هو ذراعنا المباشر — أي أداة نبنيها (طبقة 4) يجب أن تدعمه مبكراً لأنه الأرخص والأسهل:
- مواصفة مقترحة: `tools/ch341_lib.py` — غلاف pyusb فوق بروتوكول CH341 EPP/I2C/SPI (معتمد على reverse عام موثق لمكتبات مفتوحة، لا على برنامج الشركة).
